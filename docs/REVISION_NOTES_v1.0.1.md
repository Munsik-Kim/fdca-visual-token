## Quantizer evidence and remaining boundary

Both frozen quantizer source snapshots have SHA-256 `2805f27d72025b766da0ca257a7d95bc4c4ede8d79f7522b5073aa6488cfc05c`, exactly matching public `fdca/analysis/p05_influence.py`. `rtn_per_output_channel` uses `amax(dim=1, keepdim=True)` on a 2D Linear weight, hence one scale per output row, with shape `[out_features,1]` inferred from code. LinearWeightHomotopy constructs W4/W8 reconstructions using that function; both frozen runner import/use paths were read. Respective archive manifest entries match the inspected files. The receipt records sanitized archive-relative names, exact hashes, sizes, relevant line excerpts and this verification boundary, without publishing private archives or machine paths.

This is source evidence for the historical implementation, not a new numerical forward run or an independent attestation of every runtime tensor. This revision did not load checkpoints, recreate quantized weights, inspect scale dumps or measure packed-kernel deployment. The observed study is floating-point execution of reconstructed weight-only quantization; no speedup or VRAM reduction follows from its output discrepancies.

## Outstanding limitations

The public compact files omit full class/seed and matched coordinate/token identities, limiting independent duplication, predecessor overlap, class-cluster and identity-pairing checks. Existing internal audit assertions are identified as such. Class labels are not fabricated. A finite number of conditional rollouts leaves Monte Carlo error in m that a bootstrap over stored block means does not fully re-estimate. The preregistration files' presence and internal frozen hashes do not prove an independent external timestamp before outcomes. Hamming/global-influence theory supplies no measured LPIPS constant. Practical selection/restoration gain, architecture generality, coupling robustness and human quality/preference remain untested.
