# 다음 연구에 반영할 실행·중단 기준

[전체 보고서](REPORT_KO.md) · [실패 분석](FAILURE_ANALYSIS_KO.md)

**이 문서는 2026-11-13의 미실행 제안이다.** 기존 결과를 본 뒤 만든 연구 방향이며 사전 등록이라고 부르지 않는다. 새 실험의 표본·난수·분석·비용을 동결하기 전에는 확인 실험으로 실행하지 않는다. LT15의 예약 265클래스는 계속 미노출 상태로 둔다.

## 1. 먼저 결정할 연구 목표

| 후보 목표 | 현재 근거 | 권고 |
|---|---|---|
| 전파를 설명하는 측정·메커니즘 연구 | LT3/LT4, M-confirm, LT11에서 직접 지지 | 논문·포트폴리오의 중심으로 정리 |
| 동일 one-step R2 정책의 추가 튜닝 | LT14 gate 실패, LT16 반복 평균 약함 | 현재 형태의 확대 중단 |
| 전파를 줄이는 새 문맥 개입 | oracle/기록 문맥 진단은 유망하지만 획득 비용·품질 미검증 | 작고 제한된 개발 실험부터 |
| 다른 모델로 일반성 확인 | 현재 Tiny 중심 | 메커니즘 프로토콜을 먼저 동결한 뒤 한 모델 확장 |
| 복원 알고리즘 재개 | oracle 시점 block 2 양의 결과는 존재 | 새로운 행동/특징/평균 label 근거가 있어야 재개 |

여러 모델을 한꺼번에 돌리면 현 선택 편향 문제를 해결하지 않은 채 같은 불확실성을 복제할 수 있다. 먼저 어떤 주장 하나를 옮길지 고른다. 우선 확인할 수 있는 주장은 “동일 최초 차이·동일 후속 window에서 공통 문맥의 배치와 범위가 전파를 바꾼다”이다.

## 2. 단계 A — 기존 근거를 확정된 입력으로 사용

새 구현 전에 다음을 연구 계약에 명시한다.

1. 원 표의 추정량, resampling 단위, CI family, class reuse 관계를 그대로 기록한다. 평균 R·signed G·토큰 불일치율을 혼합한 단일 성공 점수를 만들지 않는다.
2. LT6 단독 원 compact와 원 95% 구간을 확보할 수 있다면 보완한다. 확보하지 못하면 현재 provenance 한계를 유지한다. LT7 이전 미발견 완료본을 존재한다고 추정하지 않는다.
3. 모델·quantizer·스케줄·CFG·categorical support·decoder·metric·coupling의 버전과 hash를 동결한다. “INT8”이라는 제품명으로 W8 재구성 연구를 바꾸어 서술하지 않는다.
4. 클래스와 부모·seed의 사용 이력을 ledger로 관리한다. 기존 320클래스와 LT14의 24개 개발 클래스는 독립 확인에 재사용하지 않는다. 새 클래스도 pretraining 미노출이라는 뜻이 아님을 명시한다.
5. 실패한 실행, 비용 counter 수정, 순열 재생, status snapshot과 최종 receipt를 함께 보존한다. 결과를 보기 전의 freeze와 결과 후의 설명을 파일로 분리한다.

## 3. 단계 B — 문맥 메커니즘의 제한된 일반화

한 개의 추가 모델 또는 하나의 새로운 스케줄을 먼저 선택한다. 둘을 동시에 바꾸면 원인을 분리하기 어렵다. 모델 구조와 토큰 길이가 다르면 “74좌표, 32window”의 절대 수를 그대로 쓰는 분석과 비율을 맞추는 분석 중 어느 것이 주 비교인지 미리 정한다.

| 비교군 | 맞춰야 할 것 | 식별하려는 것 |
|---|---|---|
| 문맥 없음 | 동일 첫 불일치 위치·값, 부모, 후속 좌표, suffix 난수 | 추가 공통 문맥의 총 개입 효과 |
| 원 배치의 공통 문맥 | 높은 가시 범위, 고정한 값 집합 | 기존 M-confirm 대응 |
| 섞은 배치의 공통 문맥 | 같은 가시 좌표와 값의 multiset | 배치 적합성의 추가 효과 |
| 낮은 범위 원/섞은 문맥 | 사전 정한 nested subset와 순열 규칙 | 배치 평균 가시 범위 효과 |
| 다른 출처의 공통 문맥 | 수신 클래스 쌍, 좌표 수, 방향별 대칭 교환 | 공유 효과와 출처 일치 효과 구분 |
| 동일 상태 self 대조 | 모든 토큰·난수·연산 동일 | 인위적 분기 또는 구현 누수 탐지 |

주 결과는 하나의 명확한 family로 제한한다. 예를 들어 M-confirm과 동일한 C_ctx, C_layout, C_dose의 세 대비를 주 결과로 두고, 출처 교환은 별도 동결 단계로 진행할 수 있다. 원 논문의 양의 결과에 유리한 시점만 보고 뒤늦게 고르지 않는다.

표본 수는 기존 클래스 변동과 고정 부모 MCSE를 분리하여 산정한다. 각 독립 클래스/쌍의 반복 수를 균형 있게 유지한다. 부모와 suffix 반복을 늘려도 새 클래스 수가 늘지는 않는다. 효과 방향 외에 한 토큰 같은 실용 기준을 유지할지 새 모델에 맞춰 바꿀지는 결과를 보기 전에 결정한다.

확인 성공은 지정한 model/schedule/coupling에서만 기술한다. 여러 조건 중 한 조건이 성공했다고 전체 모델 일반성으로 확대하지 않는다. 실패하면 원 결과를 지우지 않고 이질성과 적용 범위를 보고한다.

## 4. 단계 C — 진단 문맥을 실제 행동으로 바꾸기

저장된 참조 경로나 미래 토큰을 넣는 실험만으로 배포 가능한 알고리즘이 되지는 않는다. 다음 개발은 **생성 시점에 실제로 이용 가능한 문맥**을 정의하는 데서 시작해야 한다. 예를 들어 현재 이미 확정된 토큰의 재사용 또는 사전 고정한 신뢰도 기준의 보존을 고려할 수 있지만, 이러한 행동이 유효하다는 결과는 아직 없다.

| 행동 후보의 검증 항목 | 필요한 비교 |
|---|---|
| 공통 문맥을 얻는 데 추가 모델 호출이 필요한가 | 같은 총 호출 수를 단순 추가 생성·재평가에 쓴 대조 |
| 높은 confidence 토큰을 보존하는가 | 무작위 동일 개수 보존, 시간만 기준, entropy/margin 기준 |
| 토큰 값을 수정하는가 | 같은 위치·같은 수정 수의 대체 값 대조, 무개입 |
| 전파가 줄어드는가 | 고정된 최초 차이의 paired 불일치율 |
| 출력 목표도 나아지는가 | 별도의 signed G 또는 처음부터 정의한 품질 지표 |
| 오류를 두 경로에 같이 강요해 차이만 줄인 것은 아닌가 | 참조 거리와 marginal 출력 분포·품질 평가를 구분 |

두 경로가 같은 잘못된 출력으로 수렴하면 불일치율은 줄어도 좋은 생성기가 되지 않는다. 따라서 “전파 억제”와 “유용한 알고리즘”은 단계별 성공 기준을 따로 둔다. 품질을 새 목표로 삼으면 참조 LPIPS만으로 결론내지 않고 별도 평가를 설계한다.

## 5. 복원을 다시 시도할 때의 최소 조건

현 LT14 정책을 그대로 더 많은 클래스에서 시험하는 것을 기본 다음 단계로 삼지 않는다. 재개하려면 다음 중 적어도 하나의 새로운 근거가 필요하다: 실제로 방향 정보를 주는 참조 없는 특징, 평균 signed G가 양수인 새로운 행동, 또는 같은 예산 대조보다 유리한 반복 평균 정책.

실험은 다음 세 층으로 분리한다.

| 층 | 데이터 사용 | 결과 |
|---|---|---|
| 행동 가치 측정 | 개발 클래스의 저장 상태에서 독립 난수 A로 여러 번 실행 | 상태·행동의 평균 signed G와 MCSE |
| 정책 선택 | 클래스 outer fold 내 학습/튜닝; 필요 시 난수 B 별도 사용 | 참조 없는 선택 규칙 동결 |
| 정책 평가 | 선택에 쓰지 않은 난수 C, 최종적으로 새 클래스의 처음부터 실행한 경로 | paired 절대·추가 G 및 실제 비용 |

같은 부모·상태·난수의 최대값을 label과 평가에 동시에 사용하지 않는다. 후보가 많을수록 선택 낙관성이 커질 수 있으므로 후보 수, 행동 예산, threshold, hyperparameter 범위를 먼저 제한한다. train/test 간 prefix나 reference suffix의 재사용도 기록한다. 참조는 오프라인 label 또는 평가에만 사용하고 실행 시 선택 입력에 섞지 않는다.

필수 대조는 **무개입 Q, 개발에서 동결한 고정 시점, 시간만 사용, entropy, 동일 정보·동일 행동의 간단한 정책, 같은 전체 계산 비용 대조**다. 새로운 특징을 쓰는 정책이 더 많은 forward를 사용한다면 그 차이를 숨기지 않는다. 여러 이름이 같은 시점을 고르면 alias를 합쳐 실제 행동 수와 독립성 수준을 보고한다.

## 6. 사전 동결해야 할 gate

아래는 gate의 구성안이다. 새 실험의 확정 숫자로 이미 승인된 것이 아니다. 예전 +0.005 추가 이득·+0.01 절대 이득·한 토큰 문맥 기준을 그대로 쓸지 비용과 목표에 맞게 바꿀지 먼저 결정해야 한다.

| gate | 통과 조건의 구성 | 실패 시 행동 |
|---|---|---|
| 기술 gate | 모델/quantizer hash, self 대조, RNG replay, 경로 누락 0, 예산 계측 | 과학 표본을 열기 전에 수정; 실패 기록 유지 |
| 가치 gate | 선택 난수와 분리된 반복 평균 G; 양·음 기여 및 MCSE 보고 | 최대 관측값으로 대체하지 않고 행동 재검토 |
| 개발 gate | 클래스 OOF에서 강한 대조 대비 사전 실용 차이, fold 안정성, 전체 비용 충족 | 확인 holdout 접근 0, `NOT_STARTED` 기록 |
| 확인 gate | 동결된 두 핵심 대비의 다중 비교 보정 CI와 실용 경계 충족 | 성공 주장 보류; 부분 성공은 그대로 한정 |
| 일반화 gate | 미사용 모델/설정에서 동결 프로토콜 확인 | 적용 범위 제한 또는 이질성 보고 |

확인 평가를 연 뒤 기준·표본 수·주 결과를 바꾸려면 원 판정과 deviation을 별도로 공개한다. 반복 분석으로 유리한 구간을 찾지 않는다. 합리적인 최대 예산과 중단 규칙을 먼저 정하고, 단순 유의성 도달을 목표로 반복 수를 늘리지 않는다.

## 7. K만 늘리는 접근의 한계

분산이 유지된다는 가정에서 K=8을 32로 늘리면 고정 상태 평균의 MCSE가 대략 절반이 될 수 있다. 이는 계산상 예상이지 새로 검증된 결과가 아니다. 클래스 일반화나 단일 최대 선택의 편향을 자동으로 해결하지도 않는다. LT16의 1,264실험은 과학·기술 감사 원자료만 약 63.43GB였으므로 반복 확대는 저장·감사 비용도 함께 산정해야 한다.

MCSE 축소가 필요한지 먼저 효과 크기와 의사결정 경계를 비교한다. 현 C 구간은 이미 ±0.005 내부다. 동일한 특징·행동에서 반복만 늘려 현 정책의 목표 이득을 만들어낼 수는 없다.

## 8. 후속 연구가 받아야 할 산출물

다음 실행에는 동결 계약, 모델/스케줄/결합 manifest, 클래스 사용 ledger, 후보·정책 alias 표, class/seed/state/draw 식별자, signed endpoint와 원 denominator, 전체 비용 계측, 독립 수치 검산, 실패·재개 이력, compact replay를 포함한다. 원자료 전체와 공개 compact의 검증 범위를 분리하고, 과학적 판정과 기술 PASS를 별도 필드로 둔다.

이 보고서와 공개 재생 패키지는 그 출발점이다. 새로운 실험을 시작했다는 의미는 없으며, LT15와 예약 265클래스의 미실행 상태를 바꾸지 않는다.
